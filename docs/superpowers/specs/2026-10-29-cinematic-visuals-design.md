# 夜巷求生 — 写实电影感画面大改设计

日期：2026-10-29  
状态：待用户审阅  
范围：纯画面与渲染；玩法数值、波次、弹药逻辑保持不变（除非碰撞盒因模型尺寸需要微调）。

## 背景

当前版本用纯色 `BoxGeometry` 拼楼和丧尸，无贴图、无外部模型，用户反馈「画面太糙太丑」。方向定为**写实电影感 demake 级**：更好的贴图、灯光与雾，接近可演示的独立游戏截图质量。

## 目标与非目标

**目标**

- 夜巷城市块看起来像「废弃街区 demake」，不是灰盒子。
- 丧尸与第一人称手枪有可读的形体与材质，不再是方块人。
- 冷月光 + 暖路灯、指数雾、暗角与轻 bloom，整体偏电影夜戏。
- 普通笔记本浏览器目标 **≥30fps**（1280×800 左右）。

**非目标**

- 不改核心玩法循环（波次、射击、拾取、死亡重开）。
- 不引入付费资产或需登录的商店包。
- 不做完整开放世界或多街区流式加载。
- 不追求 AAA 面数或实时 GI。

## 方案选型（已批准）

**路线 B：免费 glTF 资产 + 灯光雾与后处理**

- 引入 CC0 / CC-BY 可商用的城市、丧尸、手枪 glTF/GLB。
- 重做场景装配、灯光、雾、后处理。
- 失败回退：贴图方块场景（保留可玩）。

备选已否决：A 纯程序化（快但假）、C Blender 全自建（太慢）。

## 资产策略

| 角色 | 要求 | 备注 |
|------|------|------|
| 城市街区 | 路、人行道、若干楼、路灯或等效光源位 | 优先一整块可缩放的街区或可拼装模块；本地 vendoring 到 `assets/` |
| 丧尸 | 人形可走/待机；皮肤偏苍白或腐烂可读 | 可实例化；碰撞仍用胶囊/圆柱近似 |
| 手枪（FPS 视角） | 第一人称手臂+枪或独立枪模 | 对齐现有 `weapons.js` 开火点与后坐 |
| 贴图/材质 | 随 glTF 自带 PBR；必要时补一张地面/沥青 | 禁止热链到不可靠 CDN 作为唯一来源 |

许可证：只收录明确 CC0 / CC-BY / 等价「可商用免费」来源，在 `assets/CREDITS.md` 写清作者与链接。

找不到合适免费包时的降级：程序化楼体 + 高分辨率程序/平铺贴图 + 简化丧尸 mesh（胶囊+头），仍做完整灯光雾。

## 场景与装配

- 保留现有可玩区域尺度（约 80×80 量级街区、十字路），把 glTF 缩放/对齐到现有碰撞与出生点。
- 碰撞：继续用 AABB（或从楼体包围盒生成）；不依赖复杂 mesh collider。
- 出生点、补给点坐标按新布局微调，逻辑接口不变。
- 雾色与背景色统一为冷蓝灰夜空，避免「亮背景 + 暗雾」割裂。

## 灯光与后处理（已批准）

- **环境**：Hemisphere 冷上暖下，强度适中。
- **月光**：Directional，偏冷白/蓝，可开阴影（距离与 mapSize 裁短保帧率）。
- **路灯**：若干 Point/Spot，暖橙，带衰减；与模型灯位对齐。
- **雾**：`FogExp2`，密度调到街尽头略糊、近处清晰。
- **后处理**：EffectComposer — 渲染通道 + 轻 UnrealBloom（或等价）+ 暗角；bloom 克制，避免霓虹感。
- **曝光**：tone mapping（ACES 或 Reinhard）+ 固定 exposure，避免再次「一团黑」或「过曝灰」。

## 技术约束

- 栈：浏览器 Three.js（现有 r160 ES modules）+ 本地 `python -m http.server`（或等价）。
- 加载：`GLTFLoader`；大资源可压缩 Draco 若资产自带。
- 性能：阴影灯数量有上限；远距物体可简化；目标 30fps+。
- 兼容：Chrome/Edge 桌面；不保证移动端。

## 验收标准

1. 冷启动进入游戏后，截图/录屏中街道、楼、灯可读，不再是纯色方块墙。
2. 丧尸与手枪在 5 米内可辨认形体，非方块人。
3. 夜戏氛围：冷月光 + 暖路灯 + 雾 + 暗角可见；不过曝、不过黑到看不清 HUD 外场景。
4. 本机桌面 Chrome 游玩波次 1 不少于 30 秒无明显卡成幻灯。
5. `assets/CREDITS.md` 完整；无未授权资产。
6. 玩法：移动、射击、受伤、死亡重开、波次 UI 仍可用。

## 风险

- 免费丧尸/城市包质量参差 → 多源筛选 + 降级方案。
- glTF 朝向/比例错 → 统一缩放与 forward 约定。
- 后处理吃帧 → bloom 可关、阴影可关的调试开关。
- 许可证不清 → 不用该资产。
